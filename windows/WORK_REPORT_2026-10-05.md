### 验收发现的问题（已修复）

IO1–IO5 交付后经过两轮验收，下面是第二轮（`775f77e`）修复的缺陷，每项都有回归测试。第一轮的修复见上表 `d0aeac3`。

| 范围 | 问题 | 修复后 |
| --- | --- | --- |
| IO3 历史预算 | 每次编辑都要序列化全部 40 步历史来估算内存，400 图层文档每步约 110 ms | 每步只测一次，60 次编辑从 6.5 s 降到 0.54 s |
| IO1 项目哈希 | 打开和保存时在界面线程计算整个项目的哈希，157 MiB 项目保存时界面最长卡顿约 2 s | 改在后台计算，最长卡顿 44 ms |
| IO1 损坏项目 | 项目引用的图片被删除后，Ctrl+S 直接失败 | 视为磁盘上的外部修改，确认后可以覆盖保存 |
| IO1 / IO2 路径大小写 | 只有大小写不同的路径会打开两个标签页，同时监视和保存同一个文件夹 | 路径比较不区分大小写 |
| IO5 真实 PSD | 用户提供的海报 PSD（5400×7200，`新版射艺.psd`）：PostScript 字体名匹配不到已安装字体，导致丢字；混排字体只保留第一种；段落文字每行下移 15 px | 以 Photoshop 自身合成图为参照，平均误差 2.62 降到 0.15，差异像素 1.96% 降到 0.12%，每行文字偏移 0 px |
| IO5 矢量蒙版 | 没有像素数据的矢量填充图层，其像素蒙版被拉伸 | 蒙版保持在画布上的原位置 |

- **项目监视（`project_io`）**：缺失和无法读取的资产都计入指纹标记，同时保留 512 MiB 文件上限；保留自适应审计间隔，与后台基线哈希一起工作。

- **`editor.cpp`**：关闭文档时先合并浮动选区，再做保存检查。
- **文档**：移植状态表按各自负责的行取舍；IO 报告两轮验收的章节都保留。

## 四、尚未完成的功能

按领域列出，每一项都来自现有报告的限制说明或代码核对，不包含新的猜测。

1. **界面（U1）**
   - 工具栏仍是窗口顶部的文字按钮。需要改为左侧竖排的单色图标工具栏，并把同类工具折叠成组。
   - 没有应用图标和 Windows 版本资源：仓库里没有 `.ico` 或 `.rc` 文件。
   - 目前只有 Fusion 风格加深色调色板。
   - 需要高分屏图标。
   - 图层面板外观需要与 Mac 截图对照。
2. **变换**
   - 网格扭曲（Mesh Distort）。
   - 扭曲在松开手柄时立即生效，不能停留在待应用状态，所以每次扭曲都会再次重采样。
   - 不能单独扭曲未链接的蒙版。
3. **选区（S2 的限制）**
   - 选区仍是画布大小的灰度蒙版，移出画布的轮廓和浮动像素会丢失（原版保存矢量路径）。
   - 拖动选区轮廓时不吸附参考线。
   - 浮动选区不支持以蒙版为目标。
   - 缺少调整边缘（Refine Edge）。
4. **滤镜与调整（F1–F4 的限制）**
   - 正在运行的预览计算不能中途打断，只能丢弃结果。
   - 点「确定」后的全分辨率应用仍在界面线程同步执行，大图会卡住界面。
   - 杂色、颗粒、抖动在缩小的预览中颗粒感与最终结果不同。
   - 图层越界扩展后保留透明边距，不会自动裁回。
   - 图层效果对话框仍是模态的，没有画布实时预览。
   - 另外 9 种调整仍使用通用的滑块面板，是否需要像原版那样的专用面板，要与 Mac 对照后确定。
   - Camera Raw 面板是固定在窗口右缘的工具窗口，不能拖入布局；在画布上绘制几何参考线时不显示临时线段。
5. **绘画**
   - 笔刷动态。
   - 模糊、涂抹、液化仍是固定边界。
   - 蒙版边缘背景与 Mac 的一致性。
6. **文件格式（IO5 / IO4）**
   - PSD 效果：不支持渐变叠加、图案叠加、斜面与浮雕、光泽；同类效果有多个实例时只保留第一个。
   - PSD 数据：不支持 16 / 32 位、CMYK / Lab 和 ZIP 压缩通道；任意路径不能保存为可编辑矢量；智能对象只保留像素；竖排文字只保留像素。
   - HEIC：缺少旋转的 iPhone 实拍样本。
   - RAW：缺少真实相机样本（CR3、NEF、ARW、RAF、手机 DNG）。
7. **AI**
   - 正式模型的托管地址还没有发布，下载入口仍然禁用。
   - 抠图质量的人工验收、更多 Intel 核显和没有 DX12 的机器。
   - NVIDIA CUDA 暂缓。
8. **发布（D1 / D2）**
   - 安装包（计划使用 Inno Setup 或 MSIX）、代码签名、`.comp` 文件夹的「用 Compositor 打开」和文件关联。
   - 在干净机器上测试 Win10 / Win11、不同显卡、150% / 200% 缩放和多显示器。
9. **验收（Q1 / Q2）**
   - Mac 参考图库，以及把像素对比加入 CI（建议阈值：每通道最大差 ≤ 2，平均差 ≤ 0.5）。
   - 把差距文档的 48 项逐条变成交互验收步骤。
   - 6000×4000、20 图层的大文档性能和内存验收。
   - 微软拼音、搜狗等输入法的人工验收。

## 五、收尾需要准备的条件

以下条件编码无法替代，建议在下一轮开始时就去落实：

1. **一台 Mac**（Apple silicon、macOS 26、Xcode 26）：用来编译原版并导出参考图。这是 Q1 / Q2 以及各项「Mac 对照」的共同前提，也是目前最大的阻塞。
2. **代码签名证书**（OV / EV 或 Azure Trusted Signing）：身份审核需要 1–2 周，要提前申请。
3. **正式模型的托管地址**：模型选型和许可已经核实，只差发布位置和最终哈希。
4. **测试机与素材**：Win10 22H2 和 Win11 各一台；NVIDIA、AMD、Intel 核显各一种；一台高分屏；真实的 RAW、PSD 和 iPhone HEIC 样本。
5. **版本决定**：计划中 M3 对应 0.8 测试版，目前仍为 0.4.0。建议推送并确认 CI 之后，再决定是否升版本号。版本号与项目格式无关：格式只在新增保存字段时提升，今天没有新增。
