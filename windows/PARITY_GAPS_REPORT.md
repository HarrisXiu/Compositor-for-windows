# 功能缺口补齐（与 Mac 原版对齐）

分支 `feature/parity-gaps`，基于 `the-one-for-windows` 的 `d1ef79f`。应用仍为 0.4.0，`.comp` 格式仍为 11：新增的状态都只存在于会话中，不写入项目。

## 范围核对

[2026-10-05 工作报告](WORK_REPORT_2026-10-05.md) 第四节第 2–6 项列出的缺口，原本是参照 Photoshop 整理的。开发计划的目标是与 Mac 原版对齐，所以动手前先逐项查了原版源码（`Compositor/` 目录）。

**原版没有的功能，从对齐范围中移除：**

| 功能 | 原版源码中的依据 |
| --- | --- |
| 网格扭曲 | `MetalWarp.swift` 只用于涂抹和液化的 GPU 工作副本；`Distort.swift` 只有四角扭曲 |
| 调整边缘（Refine Edge） | 源码中没有；`refine` 只出现在 Camera Raw 和移除背景的参数里 |
| 笔刷动态 / 压感 | 原版没有压感（开发计划中已列为可选增强 E2） |
| 浮动选区作用于蒙版 | `FloatingSelection.swift` 要求 `!isMaskSelected` |
| 拖动选区轮廓时吸附参考线 | 原版只在裁剪拖动时吸附 |
| 单独扭曲未链接的蒙版 | `distortShape` 在 `edit.mask` 时返回 nil |
| 模糊、涂抹、液化越界扩展 | `BlurTool.swift` 的范围固定为原图层大小 |
| 中途打断正在运行的预览计算 | 原版取消的是 Swift 任务，C 内核仍会算完，与 Windows 相同 |

**IO5（PSD）：** 原版只读 8 位 RGB、raw/RLE 压缩的 PSD，智能对象和竖排文字只保留像素，图层效果则**直接丢弃**（`PSDDocumentBuilder.swift`：“Layer effects were discarded”）。Windows 已经能转换六种效果、读取 Bezier 蒙版和灰度文件，已超出原版。剩下的 16/32 位、CMYK/Lab、ZIP 压缩、斜面浮雕等属于 Photoshop 兼容增强，不是对齐缺口。

**素材验证与 AI 质量：** 需要真实 iPhone HEIC、相机 RAW 样本和人工判断，不在本分支范围内。

## 本次补齐的 6 项

| 提交 | 内容 |
| --- | --- |
| `fb25ff7` | 两项：**调整面板**——色彩平衡按阴影、中间调、高光分组，每个轴向显示原版的对色轨道；黑白的六个色系轨道从该色暗部到亮部，「色调」的色相和饱和度只在勾选时显示，饱和度轨道随色相变化；渐变映射显示两端的渐变条和色块，「反向」时交换。**后台应用**——点确定后，全分辨率结果在后台线程根据文档快照计算，预览一直显示在画布上，完成后作为一步撤销替换图层；计算期间只能平移和缩放，其他命令被忽略，关闭窗口要等计算完成，外部重新载入会推迟 |
| `9397dde` | **蒙版的边缘色调**：与图层分开放置的蒙版，在图层上超出蒙版像素的区域显示边缘多数像素的色调（白或黑）。全显蒙版移开后图层仍然可见，全隐蒙版仍然隐藏。绘画扩展蒙版、扭曲蒙版、在蒙版上使用模糊画笔，都用同一色调填补蒙版像素以外的区域。渲染时从全显区域中扣除蒙版遮住的部分，蒙版放在小数坐标时边缘也没有接缝 |
| `73829c6` | **扭曲保持待应用**：Ctrl 拖动手柄松开后，不再立即重新采样像素。文档保留原像素，画布用实时预览显示扭曲效果。之后拖动手柄不需要再按 Ctrl 就会继续扭曲，在其他位置拖动会整体移动。按 Enter、切换工具或执行其他命令时，以全分辨率应用一次，计为一步撤销；Esc、撤销、重做会放弃这次扭曲。提交或取消浮动选区时，先处理其上的扭曲 |
| `995e013` | **图层效果实时预览**：效果面板改为非模态，停在画布旁边；参数变化直接显示在画布上（只改画布绘制用的文档副本）；数值都带滑块和可拖动标签。确定后记录一步「Edit Effect」，取消则不留痕迹 |
| `828d392` | **选区轮廓可以移出画布**：拖动或用方向键移动轮廓，以及移动选中像素时，移出画布的部分不再丢失，移回来时完整无缺。画布大小的选区仍是所有功能读取的数据；会话按这份选区图像的 cacheKey 保存完整选区，撤销和重做恢复的是同一图像，因此同样能找回；其他任何选区修改都会生成新图像，旧的完整选区就不再使用。只保存实际覆盖的范围，总量限制在 256 MiB 以内 |

## 仍未做的

- 与 Mac 的像素和交互对照仍需要一台 Mac。
